# ESP32-S3 (N16R8) 说明

## 板型参数（生成固件时实际使用的）

```
FQBN          esp32:esp32:esp32s3:FlashSize=16M,PSRAM=opi,PartitionScheme=esp_sr_16
Flash         16 MB
PSRAM         8 MB（OPI，需要 PSRAM=opi）
分区          应用 3 MB（app0 @0x10000）、文件系统 6 MB（spiffs @0x610000）
二级引导程序  0x0（注意：ESP32 DevKit 是 0x1000，S3/C3 是 0x0）
esptool chip   esp32s3
全量缓存上限  5 766 168 B（5.5 MB，即 6 MB 文件系统留出元数据余量）
```

对比现有板型：

| 板型 | Flash | 文件系统 | 全量缓存上限 | 链路 |
|---|---|---|---|---|
| ESP-01S | 1 MB | 无 | 不支持 | 仅流式 |
| ESP-12E / NodeMCU | 4 MB | 1 MB | 896 KB | 三种 |
| ESP32 DevKit | 4 MB | 1.4 MB | 1.4 MB | 三种 |
| **ESP32-S3 (N16R8)** | **16 MB** | **6 MB** | **5.5 MB** | **三种** |

## 传输设置里的「SW 远程烧录/调试」

**当前是占位，未实现。**

- 面板「烧录设置 → 传输」里会显示 `⚠ 暂未实现 · SW 远程烧录/调试（ESP32-S3）`；
- 可以选中并保存，但**点烧录会明确报错**：`「SW 远程烧录/调试」尚未实现：请把传输改回 ST-Link / 串口 / Wi-Fi`；
- 这样做是为了不让界面出现"看起来能用、点了没反应"的按钮。

真正的远程 SWD 需要 ESP32-S3 侧跑 **CMSIS-DAP 固件**，把 SWCLK/SWDIO 上的调试包经 Wi-Fi 隧道转发给 PC 上的 OpenOCD / pyOCD。那是独立的一条链路，与现在的 AN3155 串口烧录互不相干，落地时再单独设计（也才轮得到"调试"：断点、单步、读寄存器）。

## 这块板还能做什么（同一用途下）

| 能力 | 说明 | 依赖 |
|---|---|---|
| **USB 原生 CDC 控制台** | S3 自带 USB-OTG（GPIO19/20），不需要 CH340 也能当串口给电脑；Wi-Fi 挂了还有一条路 | 固件加 USB CDC |
| **PSRAM 直写镜像** | 8 MB PSRAM 可以先把镜像整块收进内存再落盘/自烧，不经过文件系统，速度和磨损都更好 | 固件 |
| **真正的无线 SWD 调试** | CMSIS-DAP over Wi-Fi，实现断点/单步/寄存器 | 独立固件 + OpenOCD |
| **双串口分流** | S3 有 UART0/1/2 + USB CDC：一路烧录、一路监听（比如 K230 的高频数据），物理上分开就不会互相干扰 | 固件 |
| **长时串口录制** | 8 MB PSRAM/16 MB Flash 可以录很久的串口波形，事后回放到面板 | 固件 |
| **ESP 自身 OTA** | 不用拆线就能升级 ESP 固件 | 固件 |
